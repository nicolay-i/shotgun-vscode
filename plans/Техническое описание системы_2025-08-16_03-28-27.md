## Техническое описание проекта: AI Code Assistant

### 1. Обзор архитектуры

Проект представляет собой **расширение для Visual Studio Code**. Архитектурно он разделен на две основные части, которые взаимодействуют друг с другом:

1.  **Backend (Extension Side):** Это код, который выполняется в основной среде Node.js в VS Code. Он находится в директории `src/`. Эта часть отвечает за всю "тяжелую" логику: работу с файловой системой, взаимодействие с внешними AI API, безопасное хранение ключей и управление состоянием Webview.

2.  **Frontend (Webview Side):** Это **React-приложение**, которое рендерится внутри панели VS Code (Webview). Оно находится в директории `webview-ui/`. Эта часть отвечает исключительно за пользовательский интерфейс, отображение данных и отправку действий пользователя на Backend.

Взаимодействие между Backend и Frontend происходит асинхронно через **API обмена сообщениями** (`postMessage`), предоставляемый VS Code. Это классическая клиент-серверная архитектура, где Backend — это сервер, а Frontend — клиент.

**Ключевые архитектурные паттерны:**

*   **Стратегия (Strategy Pattern):** Используется для работы с различными AI-провайдерами (`src/providers/`). Каждый провайдер (OpenAI, Gemini и т.д.) является отдельной "стратегией" отправки запроса. Это позволяет легко добавлять новые AI-сервисы, не меняя основной код.
*   **Фабрика (Factory Pattern):** `ProviderFactory` (`src/providers/ProviderFactory.ts`) отвечает за создание нужного экземпляра провайдера по запросу. Это централизует управление провайдерами.
*   **Сервисный слой (Service Layer):** Логика работы с файловой системой (`FileSystemService`) и секретами (`VsCodeSecretStorageService`) вынесена в отдельные сервисы с четкими интерфейсами (`IFileSystemService`, `ISecretStorageService`). Это улучшает тестируемость и разделение ответственности.
*   **Централизованное управление состоянием (State Management):** На фронтенде используется **MobX** для управления состоянием UI. Это обеспечивает предсказуемый поток данных и автоматическое обновление компонентов при изменении стейта.

### 2. Структура проекта

Ниже представлена структура ключевых директорий и файлов с пояснениями.

```
.
├── src/                      # Backend (логика расширения)
│   ├── providers/            # Модули для работы с разными AI API
│   │   ├── IAiProvider.ts    # Интерфейс, определяющий контракт для всех провайдеров (Стратегия)
│   │   ├── GeminiProvider.ts # Реализация для Google Gemini
│   │   ├── OpenAiProvider.ts # Реализация для OpenAI
│   │   ├── CustomProvider.ts # Реализация для кастомных, OpenAI-совместимых API
│   │   └── ProviderFactory.ts# Фабрика для создания экземпляров провайдеров
│   │
│   ├── services/             # Сервисы для взаимодействия со средой VS Code
│   │   ├── IFileSystemService.ts       # Интерфейс для работы с файлами
│   │   ├── FileSystemService.ts        # Реализация работы с файлами
│   │   ├── ISecretStorageService.ts    # Интерфейс для безопасного хранения данных
│   │   └── VsCodeSecretStorageService.ts # Реализация хранения через VS Code SecretStorage API
│   │
│   ├── extension.ts          # Главный входной файл расширения. Регистрирует команды.
│   ├── ShotgunPanel.ts       # "Контроллер" для Webview. Создает панель, обрабатывает сообщения от Frontend.
│   ├── ApiService.ts         # Оркестратор запросов к AI. Формирует промпты и использует провайдеры.
│   ├── templates.ts          # Встроенные шаблоны промптов.
│   └── types.ts              # TypeScript-типы, используемые на Backend.
│
└── webview-ui/               # Frontend (React-приложение для Webview)
    └── src/
        ├── components/       # UI-компоненты React
        │   ├── ApiSettings.tsx     # Компонент для настройки API ключей и моделей
        │   ├── FileTree.tsx        # Компонент для отображения дерева файлов проекта
        │   ├── PromptSection.tsx   # Поле ввода промпта и кнопки отправки
        │   ├── ResponseSection.tsx # Отображение ответа от AI
        │   └── TemplateManager.tsx # Управление шаблонами промптов
        │
        ├── stores/           # MobX-сторы для управления состоянием
        │   ├── AppStore.ts         # Глобальное состояние (загрузка, ошибки)
        │   ├── ApiStore.ts         # Состояние настроек API
        │   ├── FileStore.ts        # Состояние дерева файлов и выбранных файлов
        │   ├── PromptStore.ts      # Состояние текущего промпта и ответа AI
        │   ├── TemplateStore.ts    # Состояние шаблонов
        │   └── RootStore.ts        # Корневой стор, объединяющий все остальные
        │
        ├── contexts/         # React Context для предоставления сторов компонентам
        │   └── StoreContext.tsx
        │
        ├── styles/           # SCSS-стили
        │   └── App.scss
        │
        ├── App.tsx           # Корневой компонент приложения, обработчик сообщений от Backend.
```

### 3. Ключевые модули и их взаимодействие

1.  **`extension.ts` (Backend):** Точка входа. При выполнении команды `ai-assistant.openPanel` он создает или показывает экземпляр `ShotgunPanel`.
2.  **`ShotgunPanel.ts` (Backend):** Центральный хаб на бэкенде.
    *   Создает `WebviewPanel` и загружает в нее скомпилированный HTML/JS из `webview-ui`.
    *   Слушает сообщения от фронтенда (`onDidReceiveMessage`).
    *   Использует `FileSystemService` для получения дерева файлов и их содержимого.
    *   Использует `VsCodeSecretStorageService` для сохранения и загрузки API-ключей.
    *   При получении запроса на анализ кода, он обращается к `ApiService`.
    *   Отправляет результаты (дерево файлов, ответ AI) обратно на фронтенд.
3.  **`ApiService.ts` (Backend):** "Мозг" обработки AI-запросов.
    *   Получает от `ShotgunPanel` задачу, выбранные файлы и настройки API.
    *   Форматирует финальный `systemPrompt` и `userPrompt` на основе выбранного шаблона.
    *   Через `ProviderFactory` получает нужный экземпляр `IAiProvider`.
    *   Вызывает метод `sendRequest` у провайдера и возвращает результат.
4.  **`App.tsx` (Frontend):** Центральный хаб на фронтенде.
    *   В `useEffect` подписывается на сообщения от бэкенда.
    *   При получении сообщений (`fileTree`, `aiResponse` и т.д.), он вызывает соответствующие методы в MobX-сторах для обновления состояния.
    *   Рендерит основные компоненты UI.
5.  **Компоненты (`*.tsx`) (Frontend):** Отображают данные из MobX-сторов. При действиях пользователя (клик по кнопке, выбор файла) они вызывают методы сторов или отправляют сообщения на бэкенд через `appStore.sendMessage`.
6.  **Сторы (`*.ts` в `stores/`) (Frontend):** Хранят состояние UI. Например, `FileStore` хранит все дерево файлов и список выбранных файлов. Когда `App.tsx` получает новое дерево, он вызывает `fileStore.setFileTree()`, и все компоненты, использующие это дерево, автоматически перерисовываются.

### 4. Поток данных

Рассмотрим типичный сценарий: **пользователь отправляет запрос к AI**.

1.  **UI (Frontend):** Пользователь выбирает файлы в компоненте `FileTree.tsx`, вводит текст в `PromptSection.tsx` и нажимает "Отправить".
2.  **Действие в компоненте:** `PromptSection.tsx` вызывает метод `handleSubmit`, который через `appStore.sendMessage` отправляет на бэкенд сообщение типа `submitToAI`. Это сообщение содержит текст промпта, **пути** к выбранным файлам и конфигурацию API из `ApiStore` и `FileStore`.
3.  **Обработка на бэкенде:** `ShotgunPanel.ts` получает это сообщение.
4.  **Чтение файлов:** `ShotgunPanel` использует `FileSystemService`, чтобы прочитать содержимое каждого файла по полученным путям.
5.  **Запрос к AI:** `ShotgunPanel` передает промпт, содержимое файлов и конфиг в `ApiService.sendRequest`.
6.  **Выбор провайдера:** `ApiService` через `ProviderFactory.getProvider` получает нужный провайдер (например, `OpenAiProvider`).
7.  **Внешний вызов:** `OpenAiProvider.sendRequest` делает HTTP-запрос к API OpenAI.
8.  **Возврат ответа:** Ответ от API возвращается по цепочке: `OpenAiProvider` -> `ApiService` -> `ShotgunPanel`.
9.  **Отправка на фронтенд:** `ShotgunPanel` отправляет на фронтенд сообщение `aiResponse` с полученным текстом.
10. **Обновление состояния:** `App.tsx` получает сообщение и вызывает `promptStore.setAiResponse(message.data)`.
11. **Перерисовка UI:** Стор `PromptStore` обновляется. Компонент `ResponseSection.tsx`, который "наблюдает" за этим стором, автоматически перерисовывается и отображает ответ.

### 5. Руководство для разработчика

#### Где искать код?

*   **Логика отправки запроса к Gemini?**
    *   `src/providers/GeminiProvider.ts`
*   **UI-компонент, отвечающий за выбор файлов?**
    *   `webview-ui/src/components/FileTree.tsx`
*   **Обработка сообщения `getFiles` на бэкенде?**
    *   `src/ShotgunPanel.ts`, внутри метода `_handleMessage`.
*   **Хранение состояния API-ключей на фронтенде?**
    *   `webview-ui/src/stores/ApiStore.ts`
*   **Встроенные шаблоны промптов?**
    *   `src/templates.ts` (на бэкенде) и дублируются в `webview-ui/src/stores/TemplateStore.ts` (на фронтенде).
*   **Главный layout приложения?**
    *   `webview-ui/src/App.tsx`

#### Добавление нового функционала

**Пример: Добавить поддержку нового AI-провайдера (например, Anthropic)**

1.  **Backend:**
    *   Добавь `Anthropic = 'anthropic'` в `enum ApiProvider` в файле `src/types.ts`.
    *   Создай новый файл `src/providers/AnthropicProvider.ts` по аналогии с `OpenAiProvider.ts`, реализовав в нем интерфейс `IAiProvider`.
    *   Зарегистрируй новый провайдер в `src/providers/ProviderFactory.ts`:
        ```typescript
        private static providers: Map<ApiProvider, IAiProvider> = new Map([
            // ... existing providers
            [ApiProvider.Anthropic, new AnthropicProvider()],
        ]);
        ```
2.  **Frontend:**
    *   Добавь `Anthropic = 'anthropic'` в `enum ApiProvider` в `webview-ui/src/stores/ApiStore.ts`.
    *   В `ApiStore.ts` добавь его в `apiKeys`, `models` и `providerLabels`. Также добавь подсказки по моделям в `getAvailableModels`.
    *   Компонент `ApiSettings.tsx` автоматически подхватит нового провайдера из `ApiStore` и отобразит его в UI.

Как видишь, благодаря архитектуре (паттерны Стратегия и Фабрика) добавление нового провайдера — это четкий и изолированный процесс.

#### Стили и UI

*   Стили находятся в `webview-ui/src/styles/` и отдельных `*.scss` файлах рядом с компонентами.
*   Мы используем **SCSS** и методологию, близкую к **BEM** (например, `.response-section__header`).
*   Для соответствия теме VS Code используются **CSS-переменные**, предоставляемые редактором (например, `var(--vscode-editor-background)`). Это позволяет нашему UI автоматически адаптироваться под светлую или темную тему.

#### State Management

*   **Источник правды:** Состояние UI полностью управляется **MobX**. Никогда не храни состояние в React-компонентах (`useState`), если оно используется более чем в одном месте или является глобальным.
*   **Структура:** `RootStore` является точкой входа. Он инстанцирует все остальные сторы (`ApiStore`, `FileStore` и т.д.).
*   **Использование в компонентах:** Для доступа к сторам используй хуки из `webview-ui/src/contexts/StoreContext.tsx` (например, `useFileStore()`).
*   **Изменение состояния:** Состояние изменяется только через вызов **actions** в сторах (например, `fileStore.selectFile(node)`).
*   **Реактивность:** Оберни свои компоненты в `observer` от `mobx-react-lite`. Это обеспечит их автоматическую перерисовку при изменении данных в сторе, которые они используют.
