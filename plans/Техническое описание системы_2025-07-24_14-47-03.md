## Техническое описание проекта "AI Code Assistant"

Этот документ предназначен для быстрого погружения в проект. Он описывает архитектуру, структуру кода, ключевые модули и основные процессы разработки.

### 1. Краткий обзор архитектуры

Проект представляет собой **расширение (extension) для Visual Studio Code**, построенное по **клиент-серверной архитектуре**.

*   **"Серверная" часть (Backend)**: Это основная логика расширения, работающая в окружении Node.js внутри VS Code. Она отвечает за взаимодействие с файловой системой, API VS Code (например, для безопасного хранения ключей) и внешними AI-сервисами.
*   **"Клиентская" часть (Frontend)**: Это пользовательский интерфейс, который отображается в **Webview** внутри VS Code. Он построен на стеке **React + TypeScript + MobX + SCSS**.

Взаимодействие между Backend и Frontend происходит через асинхронный обмен сообщениями с помощью `postMessage` API, предоставляемого VS Code.

Ключевые архитектурные паттерны:
*   **Стратегия**: Используется для работы с различными AI-провайдерами (`src/providers`). Это позволяет легко добавлять поддержку новых LLM-сервисов, не изменяя основную логику.
*   **Фабрика**: `ProviderFactory` (`src/providers/ProviderFactory.ts`) инкапсулирует логику создания экземпляров провайдеров, упрощая управление ими.
*   **Инверсия зависимостей (Dependency Inversion)**: Логика зависит от абстракций (интерфейсов, например, `IAiProvider`, `IFileSystemService`), а не от конкретных реализаций. Это улучшает тестируемость и гибкость системы.
*   **State Management (Frontend)**: Используется **MobX** для централизованного и реактивного управления состоянием UI.

### 2. Структура проекта

Проект разделен на две основные части: логику расширения (`src`) и UI для Webview (`webview-ui`).

```
.
├── src/                      # Логика расширения (Backend)
│   ├── providers/            # Модули для работы с различными AI API
│   │   ├── IAiProvider.ts    # Интерфейс для всех AI-провайдеров (Стратегия)
│   │   ├── GeminiProvider.ts # Реализация для Google Gemini
│   │   ├── OpenAiProvider.ts # Реализация для OpenAI
│   │   ├── CustomProvider.ts # Реализация для кастомных OpenAI-совместимых API
│   │   └── ProviderFactory.ts# Фабрика для создания провайдеров
│   ├── services/             # Сервисы для работы с внешними системами
│   │   ├── IFileSystemService.ts # Абстракция над файловой системой
│   │   ├── FileSystemService.ts  # Реализация работы с ФС через Node.js 'fs'
│   │   ├── ISecretStorageService.ts # Абстракция для хранения секретов
│   │   └── VsCodeSecretStorageService.ts # Реализация через VS Code SecretStorage API
│   ├── ApiService.ts         # Сервис, оркестрирующий запросы к AI
│   ├── ShotgunPanel.ts       # Основной класс, управляющий Webview панелью
│   ├── extension.ts          # Точка входа в расширение (функция activate)
│   ├── templates.ts          # Предопределенные шаблоны промптов
│   └── types.ts              # Общие типы данных для Backend
│
└── webview-ui/               # UI-часть (Frontend)
    ├── src/
    │   ├── components/       # React-компоненты
    │   ├── contexts/         # React Context для MobX stores
    │   ├── stores/           # MobX-сторы для управления состоянием
    │   │   ├── AppStore.ts   # Общее состояние приложения (загрузка, ошибки)
    │   │   ├── ApiStore.ts   # Состояние настроек API
    │   │   ├── FileStore.ts  # Состояние дерева файлов и выбранных файлов
    │   │   ├── PromptStore.ts# Состояние промпта и ответа AI
    │   │   ├── TemplateStore.ts # Состояние шаблонов промптов
    │   │   └── RootStore.ts  # Корневой стор, объединяющий все остальные
    │   ├── styles/           # SCSS стили
    │   ├── App.tsx           # Корневой компонент приложения
    │   └── index.tsx         # Точка входа в React-приложение
    └── tsconfig.json         # Конфигурация TypeScript для UI
```

### 3. Ключевые модули и их взаимодействие

1.  **`extension.ts`**: Регистрирует команду `ai-assistant.openPanel`, которая запускает все остальное.
2.  **`ShotgunPanel.ts`**: "Мозг" бэкенда. Создает и управляет Webview панелью. Он выступает в роли контроллера, который:
    *   Инициализирует сервисы (`FileSystemService`, `VsCodeSecretStorageService`, `ApiService`).
    *   Обрабатывает сообщения, приходящие от UI (`_handleMessage`).
    *   Вызывает нужные сервисы для выполнения операций (чтение файлов, отправка запросов к AI).
    *   Отправляет результаты обратно в UI через `postMessage`.
3.  **`ApiService.ts`**: Формирует промпты на основе пользовательского ввода, выбранных файлов и шаблонов. Через `ProviderFactory` получает нужный `IAiProvider` и делегирует ему отправку запроса.
4.  **`*Provider.ts`**: Конкретные реализации для взаимодействия с API (OpenAI, Gemini и т.д.). Они скрывают детали реализации каждого API за единым интерфейсом `IAiProvider`.
5.  **`webview-ui/src/App.tsx`**: Корневой компонент UI. Устанавливает слушатель сообщений от `ShotgunPanel` и передает их в соответствующие MobX-сторы.
6.  **`webview-ui/src/stores/*Store.ts`**: Хранилища состояния MobX. Они содержат всю бизнес-логику и данные на стороне клиента. Компоненты подписываются на изменения в сторах и автоматически перерисовываются.

### 4. Поток данных

Рассмотрим типичный сценарий: **отправка запроса к AI**.

1.  **UI (React Component)**: Пользователь нажимает кнопку "Отправить" в компоненте `PromptSection.tsx`.
2.  **UI (Component -> Store -> App)**:
    *   Компонент вызывает метод `handleSubmit`.
    *   Этот метод собирает данные из сторов (`promptStore`, `fileStore`, `apiStore`, `templateStore`).
    *   Вызывается `appStore.sendMessage({ type: 'submitToAI', ... })`.
3.  **UI -> Backend (postMessage)**: `AppStore` отправляет сообщение в `ShotgunPanel` через `vscodeApi.postMessage`.
4.  **Backend (Controller)**: `ShotgunPanel` получает сообщение в `_setWebviewMessageListener` и вызывает `_handleSubmitToAI`.
5.  **Backend (Services)**:
    *   `_handleSubmitToAI` использует `FileSystemService` для чтения содержимого всех выбранных файлов.
    *   Затем он вызывает `apiService.sendRequest`, передавая промпт, содержимое файлов и конфигурацию API.
    *   `ApiService` форматирует финальный промпт и через `ProviderFactory` получает нужный провайдер (например, `OpenAiProvider`).
    *   `OpenAiProvider` выполняет HTTP-запрос к OpenAI API.
6.  **Backend -> UI (postMessage)**: После получения ответа от AI, `ShotgunPanel` отправляет его обратно в UI: `this._panel.webview.postMessage({ type: 'aiResponse', data: response })`.
7.  **UI (App -> Store -> Component)**:
    *   `App.tsx` получает сообщение `aiResponse`.
    *   Он вызывает `promptStore.setAiResponse(message.data)`.
    *   MobX автоматически обнаруживает изменение в `promptStore.aiResponse`.
    *   Компонент `ResponseSection.tsx`, который подписан на этот стор, перерисовывается и отображает полученный ответ.

### 5. Руководство для разработчика

#### Где искать код?

*   **Логика взаимодействия с новым AI-сервисом**: `src/providers/`.
*   **Обработка нового типа сообщения от UI**: `src/ShotgunPanel.ts` в методе `_handleMessage`.
*   **UI-компонент (например, кнопка или поле ввода)**: `webview-ui/src/components/`.
*   **Стили для UI-компонента**: `webview-ui/src/styles/` (общие) или создайте новый `.scss` файл рядом с компонентом.
*   **Логика состояния для новой фичи в UI**: `webview-ui/src/stores/`. Вероятно, нужно будет создать новый стор или дополнить существующий.
*   **Типы данных, передаваемые через `postMessage`**: `src/types.ts`.

#### Добавление нового функционала

Рассмотрим пример: **добавление поддержки нового AI-провайдера, например, Anthropic Claude**.

1.  **Определить тип в Enum**: В `src/types.ts` добавьте `Anthropic = 'anthropic'` в `enum ApiProvider`.
2.  **Создать класс провайдера**: В `src/providers/` создайте файл `AnthropicProvider.ts`.
    *   Создайте класс `class AnthropicProvider implements IAiProvider`.
    *   Реализуйте метод `async sendRequest(...)`, который будет отправлять запрос к API Anthropic, соблюдая его формат.
3.  **Зарегистрировать в фабрике**: В `src/providers/ProviderFactory.ts` импортируйте `AnthropicProvider` и добавьте его в `Map`:
    ```typescript
    private static providers: Map<ApiProvider, IAiProvider> = new Map([
        // ... существующие провайдеры
        [ApiProvider.Anthropic, new AnthropicProvider()],
    ]);
    ```
4.  **Добавить логику в UI**:
    *   **Стор**: В `webview-ui/src/stores/ApiStore.ts` добавьте `Anthropic` в `enum ApiProvider`, в `apiKeys`, `models` и `providerLabels`.
    *   **Компонент**: Компонент `ApiSettings.tsx` автоматически подхватит нового провайдера из `providerLabels` и отобразит его в UI.
    *   **Предпросмотр (опционально)**: Если формат запроса у Anthropic отличается, добавьте `case 'anthropic':` в `generatePayloadPreview` в `src/ApiService.ts`, чтобы предпросмотр был корректным.

#### Стили и UI

*   Стили написаны на **SCSS** и находятся в `webview-ui/src/styles/`.
*   Основной файл `App.scss` содержит глобальные стили, переменные VS Code (`--vscode-foreground` и т.д.) и общие классы.
*   Для новых компонентов рекомендуется создавать отдельные `.scss` файлы (например, `ErrorNotification.scss`) и импортировать их в компонент (`ErrorNotification.tsx`). Это позволяет держать стили рядом с логикой.
*   Используйте переменные VS Code для цветов и шрифтов, чтобы UI соответствовал теме пользователя.

#### State Management

*   Состояние UI управляется с помощью **MobX**.
*   Каждая логическая часть приложения имеет свой стор (`FileStore`, `ApiStore` и т.д.).
*   Все сторы объединены в `RootStore`.
*   Компоненты получают доступ к сторам через React Context и хуки (`useStores`, `useApiStore`).
*   Чтобы компонент реагировал на изменения в сторе, его нужно обернуть в `observer` из `mobx-react-lite`.
*   **Важно**: Изменения состояния должны происходить только внутри методов, помеченных как `@action` (или с использованием `action()` из MobX), чтобы обеспечить предсказуемость и оптимизацию производительности.
