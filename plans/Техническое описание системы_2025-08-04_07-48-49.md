## Техническое описание проекта: AI Code Assistant

### 1. Краткий обзор архитектуры

Проект представляет собой **расширение для VS Code** с архитектурой **клиент-сервер**:

*   **"Сервер" (Backend)**: Это основная часть расширения, работающая в окружении Node.js самого VS Code. Здесь сосредоточена вся логика, требующая доступа к системным ресурсам: работа с файловой системой, API VS Code (команды, уведомления) и безопасное хранение ключей (`SecretStorage`).
    *   **Файлы**: `src/**/*.ts`
*   **"Клиент" (Frontend)**: Это пользовательский интерфейс, который отображается в Webview-панели внутри VS Code. Он построен на **React** с **TypeScript** и **MobX** для управления состоянием. Клиент полностью изолирован от "сервера" и общается с ним исключительно через асинхронный обмен сообщениями.
    *   **Файлы**: `webview-ui/src/**/*.tsx`

Коммуникация между Backend и Frontend происходит через `postMessage` API, предоставляемый VS Code для Webview.

### 3. Ключевые модули и их взаимодействие

Систему можно разделить на несколько логических блоков:

1.  **Backend: Ядро расширения (`extension.ts`, `ShotgunPanel.ts`)**
    *   `extension.ts`: Инициализирует расширение, регистрирует команду `ai-assistant.openPanel`.
    *   `ShotgunPanel.ts`: Создает и управляет Webview-панелью. Это главный хаб на бэкенде: он слушает сообщения от фронтенда, вызывает нужные сервисы (`FileSystemService`, `ApiService`) и отправляет результаты обратно на фронтенд.

2.  **Backend: Провайдеры AI (`src/providers`)**
    *   Реализованы паттерны **Стратегия** и **Фабрика**.
    *   `IAiProvider.ts`: Определяет единый контракт `sendRequest` для всех AI-сервисов.
    *   Конкретные классы (`OpenAiProvider`, `GeminiProvider`) реализуют этот интерфейс для своих API.
    *   `ProviderFactory.ts`: Позволяет получить нужный экземпляр провайдера по его имени, абстрагируя логику выбора от `ApiService`.

3.  **Backend: Сервисный слой (`src/services`, `ApiService.ts`)**
    *   `FileSystemService`: Инкапсулирует всю работу с файловой системой (чтение дерева файлов, получение контента).
    *   `VsCodeSecretStorageService`: Работает с безопасным хранилищем VS Code для API-ключей.
    *   `ApiService.ts`: Ключевой сервис. Он получает пользовательский запрос, выбранные файлы и шаблон, форматирует из них финальный `systemPrompt` и `userPrompt`, а затем через `ProviderFactory` отправляет запрос к выбранному AI. Именно здесь находится логика функций **"Превью"** (`generatePayloadPreview`) и **"Отправить"** (`sendRequest`).

4.  **Frontend: Управление состоянием (`webview-ui/src/stores`)**
    *   Используется **MobX**.
    *   `RootStore.ts`: Создает экземпляры всех сторов.
    *   `AppStore.ts`: Управляет глобальными состояниями (загрузка, ошибки) и содержит метод `sendMessage` для связи с бэкендом.
    *   `ApiStore.ts`, `FileStore.ts`, `PromptStore.ts`, `TemplateStore.ts`: Каждый стор отвечает за свой "кусок" состояния (настройки API, файлы, промпт/ответ, шаблоны).

5.  **Frontend: UI (`webview-ui/src/components`)**
    *   Компоненты написаны на React и являются `observer`-ами MobX, т.е. они автоматически перерисовываются при изменении данных в сторах.
    *   `App.tsx`: Корневой компонент, который содержит обработчик `window.addEventListener('message', ...)` и распределяет входящие сообщения по нужным сторам.

### 4. Поток данных

Понимание потоков данных — ключ к быстрой разработке. Рассмотрим два основных сценария.

#### Сценарий 1: Отправка запроса к AI ("Отправить")

1.  **UI:** Пользователь вводит текст в `textarea` в `PromptSection.tsx` и нажимает кнопку "Отправить".
2.  **Component:** `PromptSection.tsx` вызывает `handleSubmit`.
3.  **Store (Frontend):** `handleSubmit` вызывает `appStore.sendMessage({ type: 'submitToAI', ... })`. В `data` передается вся необходимая информация из сторов: текст промпта, список выбранных файлов, конфигурация API и шаблон.
4.  **Backend Controller:** `ShotgunPanel.ts` получает сообщение в `_handleMessage` и вызывает `_handleSubmitToAI`.
5.  **Backend Services:**
    *   `_handleSubmitToAI` использует `FileSystemService` для асинхронного чтения содержимого всех выбранных файлов.
    *   Затем он вызывает `apiService.sendRequest`, передавая туда промпт и файлы с их содержимым.
6.  **Backend AI Logic:**
    *   `ApiService.sendRequest` форматирует финальные промпты.
    *   Он вызывает `ProviderFactory.getProvider` для получения нужного AI-провайдера.
    *   Вызывается `provider.sendRequest`, который делает фактический HTTP-запрос к API (например, OpenAI).
7.  **Обратный путь:**
    *   Ответ от AI возвращается в `ShotgunPanel.ts`.
    *   `ShotgunPanel.ts` отправляет сообщение на фронтенд: `webview.postMessage({ type: 'aiResponse', data: ... })`.
    *   `App.tsx` (фронтенд) ловит это сообщение и вызывает `promptStore.setAiResponse(message.data)`.
    *   **UI:** `ResponseSection.tsx`, будучи `observer`-ом, видит изменение в `promptStore.aiResponse` и автоматически перерисовывается, отображая ответ.

#### Сценарий 2: Предпросмотр запроса ("Превью")

Этот поток очень похож на предыдущий, но короче.

1.  **UI/Component/Store (Frontend):** Все как в шагах 1-3, но вызывается `handlePreview`, который отправляет сообщение `{ type: 'generatePayloadPreview', ... }`.
2.  **Backend Controller:** `ShotgunPanel.ts` получает сообщение и вызывает `_handleGeneratePayloadPreview`.
3.  **Backend Services:**
    *   `_handleGeneratePayloadPreview` также читает содержимое файлов.
    *   Он вызывает **`apiService.generatePayloadPreview`** (ключевое отличие). Этот метод не отправляет запрос, а лишь **формирует** тело запроса (`payload`), которое *было бы* отправлено.
4.  **Обратный путь:**
    *   `ShotgunPanel.ts` получает `payload` от `ApiService` и отправляет его на фронтенд: `webview.postMessage({ type: 'payloadPreview', data: ... })`.
    *   `App.tsx` ловит сообщение и вызывает `promptStore.setPayloadPreviewData(message.data)`.
    *   **UI:** Модальное окно `PromptPreviewModal.tsx` открывается и отображает данные из `promptStore.payloadPreviewData`.

### 5. Руководство для разработчика

#### Где искать код?

*   **Хочу изменить UI-компонент (например, добавить кнопку):**
    *   Ищи нужный файл в `webview-ui/src/components/`. Например, для секции ввода промпта — это `PromptSection.tsx`.
*   **Хочу добавить новое поле в настройки API:**
    *   **UI:** `webview-ui/src/components/ApiSettings.tsx`.
    *   **State:** `webview-ui/src/stores/ApiStore.ts` (добавить поле, геттеры/сеттеры).
    *   **Types:** `src/types.ts` (обновить интерфейс `ApiConfig`).
*   **Хочу поменять логику формирования промпта:**
    *   Это происходит на бэкенде в `src/ApiService.ts`, метод `formatPrompt`.
*   **Хочу изменить логику взаимодействия с конкретным AI (например, добавить параметр в запрос к OpenAI):**
    *   Ищи соответствующий провайдер в `src/providers/`, например, `OpenAiProvider.ts`.
*   **Хочу исправить баг, связанный с выбором файлов:**
    *   Логика выбора/снятия выбора и хранения состояния — в `webview-ui/src/stores/FileStore.ts`.
    *   Отображение дерева файлов — в `webview-ui/src/components/FileTree.tsx`.

#### Как добавить новый функционал?

Рассмотрим на примере добавления **нового AI-провайдера (например, "Anthropic")**:

1.  **Типы:** В `src/types.ts` добавь нового провайдера в `enum ApiProvider`:
    ```typescript
    export enum ApiProvider {
        // ...
        Anthropic = 'anthropic'
    }
    ```
2.  **Backend (Provider):** Создай новый файл `src/providers/AnthropicProvider.ts`. Он должен реализовывать интерфейс `IAiProvider`:
    ```typescript
    import { IAiProvider } from './IAiProvider';
    // ...
    export class AnthropicProvider implements IAiProvider {
        async sendRequest(systemPrompt: string, userPrompt: string, config: ApiConfig): Promise<AiResponse> {
            // Твоя логика запроса к API Anthropic
        }
    }
    ```
3.  **Backend (Factory):** Зарегистрируй новый провайдер в `src/providers/ProviderFactory.ts`:
    ```typescript
    // ...
    import { AnthropicProvider } from './AnthropicProvider';

    export class ProviderFactory {
        private static providers: Map<ApiProvider, IAiProvider> = new Map([
            // ...
            [ApiProvider.Anthropic, new AnthropicProvider()],
        ]);
        // ...
    }
    ```
4.  **Frontend (State):** Обнови `ApiStore.ts` (`webview-ui/src/stores/ApiStore.ts`), чтобы он "знал" о новом провайдере: добавь его в `apiKeys`, `models` и `getAvailableModels`.
5.  **Frontend (UI):** Обнови `ApiSettings.tsx` (`webview-ui/src/components/ApiSettings.tsx`), чтобы добавить карточку нового провайдера в интерфейс.

Готово! Благодаря паттернам "Стратегия" и "Фабрика" добавление новой логики происходит изолированно и с минимальными изменениями в существующих модулях.

#### Стили и UI

*   Стили написаны на **SCSS**.
*   Глобальные стили и переменные, использующие CSS-переменные VS Code, находятся в `webview-ui/src/styles/App.scss`. Это позволяет нашему UI адаптироваться под текущую тему VS Code.
*   Каждый сложный компонент имеет свой собственный файл стилей (например, `ErrorNotification.scss`), который импортируется напрямую в `.tsx` файл.

#### State Management

*   Мы используем **MobX**. Если ты с ним не работал, основной принцип — `observable` данные в сторах и `observer` компоненты, которые на них подписаны.
*   Состояние четко разделено по доменам (`ApiStore`, `FileStore` и т.д.).
*   **Никогда не меняй состояние напрямую из компонента.** Всегда вызывай `action` (метод) в соответствующем сторе. Компонент должен только читать данные из стора и вызывать его методы.
*   Доступ к сторам в компонентах осуществляется через React Context и кастомные хуки (`useAppStore`, `useFileStore` и т.д.) из `webview-ui/src/contexts/StoreContext.tsx`.
